    What this build can and cannot do
    
    
      
  • 
        Fonts. By default it renders with the 14 standard PDF fonts, which
        are WinAnsi Latin. Japanese and other non-Latin text will not
        typeset, and neither will the full stdja /
        stdjabook / stdjareport classes — their own page
        furniture contains an em dash, which is already outside WinAnsi. Rather than
        silently dropping such characters, the compiler refuses and tells you.
        Pick a .ttf/.otf from your machine above and all
        of that starts working, including CJK if the font has the glyphs. The font
        never leaves your browser; bundling one here would have added megabytes to the page
        load for everyone.
      
    • 
      
  • 
        @require: works, against the bundled 0.0.6 package
        corpus listed below — the real packages, resolved by the real loader. Anything
        outside that list cannot be fetched: there is no package manager here.
      
    • 
      
  • 
        No filesystem. load-image, read-file and
        load-pdf-image take paths and have nothing to read;
        load-pdf-image is not compiled into this build at all and says so if
        you call it.
      
    • 
      
  • 
        SATySFi 0.0.6 only. The 0.1 (saphe-split)
        use-header dialect needs envelope and dependency configs read from
        disk, so it is not available in the browser.
      
    • 
      
  • 
        It is a single-threaded WebAssembly module with a fixed stack.
        A very deeply nested document can exhaust it; the page will say so, and reloading
        gives you a fresh module.
